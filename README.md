# 悦足堂 · 连锁足浴总部门店管理平台

面向连锁足浴品牌的一体化运营系统：**总部统一定价/会员/提成标准 → 门店每日上钟录单 → 交班双签字确认 → 营收自动汇总至总部看板**。零外部运行依赖（Node 内置 HTTP + JSON 文件持久化，图表/签字板均为原生实现）。

## 快速开始

```bash
npm start
# 打开 http://localhost:3000
```

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 总部 | `hq`（或 `boss`） | `123456` |
| 门店 | `s01` ~ `s06`（如 `s01` 外滩店、`s04` 北京国贸店） | `123456` |

其他命令：

```bash
npm run seed           # 重置为内置演示数据（6 店 / 65 技师 / 45 天 5487 笔账单 + 库存种子）
node test-e2e.js       # 后端业务流 API 测试（需先 npm start）
node test-inventory.js # 耗材库存业务流测试（入库/盘点/调拨/原子开单/FEFO/幂等/越权，需先 npm start）
node test-inv-dom.js   # 库存前端脚本加载冒烟（零依赖，vm 模拟浏览器）
node test-inv-render.js# 库存前端 9 个视图渲染冒烟（零依赖）
node test-dom.js       # 总部端页面集成测试（需先 npm i jsdom --no-save 且 npm start）
node test-dom-store.js # 门店端开单→双签字交班集成测试
```

数据存储于 `data/db.json`，删除后重启会自动重新生成种子数据。

## 功能总览

### 总部端
- **品牌经营看板**：全品牌总营收/客单价、会员充值总额（含赠金/卡内余额）、提成总额；各门店营收排行 TOP 榜；品类与项目销售占比环形图；近 7/30/45 天日营收趋势。
- **项目统一定价**：项目目录（时长/价格/品类/上下架），调价后所有门店即时生效；历史账单保留原价不受影响。
- **会员体系**：四级会员（银/金/铂金/至尊）门槛与折扣统一配置；充值满 3000 自动赠 10%，累计充值自动升级。
- **技师提成标准**：四个技师等级默认提成比例（25%~40%）可调；支持「项目 × 等级」专项规则（每单固定金额或自定义比例），优先级高于默认比例，开单时实时计算并展示提成依据。
- **门店管理**：门店档案、新增/编辑。
- **技师档案（全品牌）**：入职登记（培训考核记录、证书、擅长项目多选）、离职、跨店调动；调动记录独立留痕。
- **全品牌流水**：跨店账单流水、全部门店交班记录、会员充值流水。

### 耗材库存（总部端）
- **库存总览**：各门店实时可用量（现存 − 冻结，已过期不计可用）、低库存预警、30 天内临期/过期批次、在途调拨、门店库存健康度。
- **耗材与配方标准**：维护耗材档案、计量单位、安全库存；按服务项目配置「标准耗用配方」（一单耗用哪些耗材、各多少），即时下发全部门店。
- **全品牌出入库流水**：按门店/耗材/类型/日期查询完整台账（入库、开单耗用、盘盈盘亏、调拨冻结/解冻/调出/调入）。

### 耗材库存（门店端）
- **库存工作台**：本店库存、低库存与临期预警、待办调拨、进行中盘点单一屏汇总。
- **批次入库**：多明细原子提交，记录批号/供应商/单价/生产日期/有效期，过期批次拒收。
- **批次库存**：按 FEFO（临期优先）查看批次现存/冻结/可用，筛选临期与过期。
- **库存盘点**：草稿态录入实盘数；确认时盘亏按 FEFO 扣减、盘盈生成盘盈批次，任一明细承担不了盘亏则整单失败。
- **跨店调拨**：门店发起 → **调出店确认后按 FEFO 冻结库存** → **调入店签收才完成扣减并入库**；可调出店取消/撤回、调入店拒收，冻结量正确解冻。
- **开单联动**：上钟开单按项目配方原子扣减本店批次（临期优先），**库存不足整单失败**（不会出现账单已生成但库存只扣一部分）；开单页实时显示配方占用与是否充足。
- **出入库流水**：仅本店数据，支持类型/耗材/日期筛选。

### 门店端
- **门店看板**：周期/今日营收、本班次实时收款汇总（现金/刷卡/会员卡/移动支付）、趋势、品类占比、近期交班记录、一键开班。
- **上钟开单**：选择项目（自动带出总部定价）→ 技师（仅本店在职）→ 可选会员（自动折扣并校验卡内余额）；金额、折扣、技师提成实时试算；账单实时归入当前班次。
- **交班结算**：自动生成交班报表（本班接待人数、现金/刷卡/会员卡/移动支付分项、营收与提成合计、技师上钟明细）；**交班人与接班人必须在手写签字板上分别签名**方可完成交班，报表即时同步总部，支持历史回看签名。
- **技师业绩提成**：按日期区间统计每位技师上钟单数、服务时长、营收、应发提成并排名。
- **员工管理**：本店技师入职登记、考核记录追加、擅长项目维护、离职、调动到其他门店。
- **会员管理**：开卡、充值（自动赠金升级）、充值记录查询。

## 关键业务规则
- 提成计算：专项规则（项目+等级，固定额/比例）> 技师等级默认比例；每笔订单落库当时的实付与提成，事后调整标准不改历史数据。
- 会员单只能使用会员卡余额支付，余额不足直接拒绝；折扣按会员等级计算。
- 同一门店同时只允许一个进行中的班次；已交班班次不能再录单、不能重复交班。
- 门店账号只能操作本店数据（技师/会员/班次/账单/库存/调拨均有后端越权校验）；门店流水接口强制按本店过滤，总部接口门店账号一律 403。
- 交班签字以 dataURL 图片持久化，双方签名缺一不可。
- **库存原子性**：开单在单次同步执行中「先按配方对全部耗材做 FEFO 预演 → 任一不足直接 409 且不写任何数据 → 全部满足后才统一写账单+批次+会员余额」，杜绝部分扣减。
- **批次与 FEFO**：可用量 = 现存 − 冻结，已过期批次不计可用也不参与扣减；扣减顺序为有效期升序、同日按入库时间升序。
- **调拨状态机**：`requested →（调出店确认/FEFO 冻结）→ frozen →（调入店签收）→ done`；`requested` 可取消，`frozen` 可由调出店撤回或调入店拒收，二者都回写解冻流水；冻结量开单不可占用。
- **幂等**：开单、入库、调拨确认/签收、盘点确认均支持客户端 `$idem` 幂等键，重复提交返回首次结果；状态机本身也对重复确认/签收做幂等处理。

## 技术结构
```
server/
  index.js      HTTP 服务 + REST API + 鉴权 + 聚合统计（零依赖）
  db.js         JSON 持久化 + 确定性演示数据生成（含库存种子/老库迁移）
  inventory.js  耗材库存领域逻辑：批次/FEFO/盘点/调拨状态机/原子开单/幂等
public/
  index.html 单页外壳
  css/app.css        品牌主题样式
  js/
    api.js         fetch/token 封装
    ui.js          DOM/弹窗/toast/格式化
    charts.js      纯 SVG 面积图、环形图、排行榜
    signature.js   canvas 手写签字板（鼠标/触摸）
    hq.js          总部视图（技师档案/交班明细等共享函数）
    store.js       门店视图（开单页含配方占用展示）
    inv-ui.js      库存共享组件（状态标签/流水表/调拨明细）
    inv-hq.js      总部库存总览 / 耗材配方标准 / 全品牌流水
    inv-store.js   门店库存工作台 / 入库 / 批次 / 盘点 / 调拨 / 流水
    app.js         登录、布局、哈希路由
```

库存表（均在 `data/db.json`）：`units / materials / recipes / invBatches / invChecks / invTransfers / invLedger / idempotency`。
